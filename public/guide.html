  3. 能访问相关 YouTube 频道的 Google 账号。不要提供账号密码给本平台或聊天。
  4. 一个能收验证码的管理员邮箱。现在可以不确定，到第 6 步再填；填好前无法使用业务功能。
  5. 为本次项目开通 Cloudflare Workers Paid。该方案批量任务较多，按付费计划的资源限制验证；不建议直接拿免费计划跑全频道。Workers Paid 当前起价每月 5 美元，R2、队列等超出额度另计，购买前以控制台账单为准。Workers 价格 ↗

1. 新建专用数据库

  1. 打开 Cloudflare 控制台 ↗ 并选择你的账号。
  2. 找到 存储与数据库 / Storage & databases → D1 SQL Database。
  3. 点击 创建数据库 / Create database。
  4. 名称填写：feifan-web-db。
  5. 其余可用默认设置，创建。
  6. 点进新数据库，在概览找到 Database ID / 数据库 ID，复制完整 UUID。它一般是带四个短横线的完整字符串。
  7. 暂时不用创建任何表，后面网页有初始化按钮。

不要点击原来的 feifan-db 做导入、清空或初始化。 截图里 UUID 后面的省略号不能作为数据库 ID。

完成标志：D1 列表中多出 feifan-web-db，旧 feifan-db 仍在。

2. 新建封面文件桶与任务队列

R2：

  1. 打开 存储与数据库 → R2 对象存储 / R2 Object Storage。不要进入旁边的 R2 数据目录 Beta，那是另一项功能。
  2. 如首次开通，按页面提示完成开通；费用或协议由你本人确认。
  3. 点击 Create bucket / 创建存储桶。
  4. 名称填写 feifan-web-files。
  5. 存储类别使用 Standard。
  6. 创建后保持私有：不用开启 Public Development URL，也不用给桶绑定域名。

Queues：

  1. 在侧栏或控制台搜索中打开 Queues。
  2. 点击 Create queue / 创建队列。
  3. 名称填写 feifan-web-sync。
  4. 创建后即可，暂时不用手动加消费者，部署会绑定本应用。

完成标志：有 feifan-web-files 和 feifan-web-sync。Queues 配置说明 ↗

  3. 允许 Cloudflare 读取刚才的私有仓库，然后选 feifanneibupingtai。
  4. 使用 Workers 项目，名称填写 feifanneibupingtai，必须和 cloudflare.config.json 的 worker_name 一致。已有同名 Worker 时，直接进入它的 设置 → 构建 修改下面配置，不要重复创建。
  5. 构建设置按下面填：
页面字段填写值

Build command / 构建命令npm run build
Deploy command / 部署命令npm run deploy
Root directory / 根目录留空或默认 /
构建环境变量 NODE_VERSION24
  1. 关闭非生产分支的自动 Preview builds。本版只使用 main 的生产部署，避免测试分支共享生产数据。
  2. 点击部署，等待成功。
  3. 成功后记下网址，类似 https://feifanneibupingtai.你的账号子域.workers.dev。下面称它为“平台网址”。

现在打开可能看到“首次设置”或“缺少 OWNER_EMAIL”等提示，这是预期的：你还没配置账号入口。

进入此 Worker 的 Settings → Build → API token，找到它使用的部署 token。在 Cloudflare My Profile → API Tokens 编辑该 token，在目标账号范围内保留 Workers Scripts / R2 权限，并补齐 D1: Edit、Queues: Edit；保存后重试部署。不同版本的自动 token 权限会不同，以缺失资源的错误为准。token 只放 Cloudflare，不上传 GitHub，不发到聊天。

6. 开启邮箱登录，并选管理员

这是你决定管理员邮箱的时机。登录平台的邮箱和授权频道的 Google 账号可以不同。

  1. 打开刚部署的 feifanneibupingtai Worker → Access 标签页。
  2. 如果看到 设置 Zero Trust 按钮，先点击它，按向导建立团队，选择适合 1—10 人试用的免费方案并完成设置。团队域名格式为 你的团队名.cloudflareaccess.com；它不是平台网址。已有团队可跳过此项。
  3. 回到此 Worker 的 Access 标签页，点击 Protect this Worker behind Access，范围选择 All traffic。旧界面可从 Settings → Domains & Routes 中 workers.dev 网址旁的 Enable Cloudflare Access 进入。不要在账号总览点 Protect all Workers，以免影响其他软件。
  4. 建立用于此 Worker 的 Access 应用，保护整个 Worker 或整个 workers.dev 主机，包括 /api/ 和 /oauth/callback。
  5. 点 Manage Access / 管理 Access 查看策略。
  6. 策略使用 Allow，Include 条件选择 Emails，只填管理员自己的邮箱。
  7. 登录方式选择 One-time PIN / 邮箱验证码（有现成受信登录方式也可以用）。
  8. 删除或收紧自动生成的宽泛允许规则。不要用 Everyone，不设置绕过 /api/ 的 Bypass 规则。
  9. 保存。
  10. 在 Access 应用的 Overview / 设置中复制 Application Audience (AUD) Tag。不要复制成应用 ID。
  11. 记下团队域名和 AUD，下一步需要。

Cloudflare 控制台若显示新版“Worker 级 Access”，优先启用它，它会统一保护 Worker 的入口。Worker Access ↗

完成标志：用无痕窗口访问平台网址会要求登录，未加入名单的邮箱不能进入。先只加你自己，后面再加员工。

7. 填四个运行变量

  1. 回到 Worker → Settings → Variables and Secrets。
  2. 注意不是 Build variables。 构建变量在程序运行时读取不到。
  3. 添加以下四项：
名称类型内容
OWNER_EMAILText / 明文变量第 6 步选定的管理员邮箱
ACCESS_TEAM_DOMAINText你的团队名.cloudflareaccess.com，不加路径
ACCESS_AUDText第 6 步复制的完整 AUD
TOKEN_KEYSecret / 密钥下一段生成的 32 字节 Base64 密钥

生成 TOKEN_KEY：

  1. 打开本地“开始部署.html”，找到“生成初次部署密钥”。
  2. 点击生成，复制显示出的整串字符，粘贴到 Cloudflare 的 TOKEN_KEY。
  3. 另外保存在你的密码管理器里。不要发给员工，不上传 GitHub，也不要在用了一段时间后随手换掉它。 数据库中的 Google 凭据依赖它解密。
  4. 点击 Cloudflare 的 Save and deploy / 保存并部署。

不要在线上设置 LOCAL_DEV。PUBLIC_URL 可以先不填，系统默认使用当前访问的网址作为回调地址。

管理员邮箱留空时，平台拒绝开放业务接口；它不会把第一个来访者自动变成管理员。

9. 配置 Google 网站授权

旧本地程序的“桌面客户端”不能直接拿来用。可以使用同一个 Google Cloud 项目，但要再建一个 Web 应用 OAuth 客户端。

  1. 打开 Google Cloud Console ↗。
  2. 选已有项目或新建项目。
  3. 打开 APIs & Services → Library / API 库，搜索并启用这三个：
  • YouTube Data API v3
  • YouTube Analytics API
  • YouTube Reporting API
  1. 打开 Google Auth Platform / OAuth consent screen，填写应用名称“飞凡内部数据平台”和你自己的联系邮箱。
  2. 如果不是同一 Google Workspace 组织的内部应用，选择 External / 外部。
  3. 验证阶段保持 Testing / 测试；在 Audience / Test users 中加入将用来授权频道的 Google 账号邮箱。
  4. 在 Data Access / Scopes 中添加：
  • https://www.googleapis.com/auth/youtube.readonly
  • https://www.googleapis.com/auth/yt-analytics.readonly
  • 需要收入时再添加 https://www.googleapis.com/auth/yt-analytics-monetary.readonly
  1. 打开 Clients / Credentials → Create OAuth client ID。
  2. Application type 选 Web application / Web 应用。
  3. 回到平台的 连接与设置，点击 复制回调地址。
  4. 在 Google 的 Authorized redirect URIs / 已获授权的重定向 URI 粘贴该地址。必须是完整 HTTPS 平台网址加 /oauth/callback，不能少字符或多斜杠。
  5. Authorized JavaScript origins 无需为本项目另外添加；授权由后端处理。
  6. 创建后下载 JSON。
  7. 回到平台，点击 导入 Web OAuth JSON，选择这个文件。平台会加密保存它，普通员工看不到。

外部 Testing 应用的这类刷新授权通常 7 天失效，届时要重新连接。正式长期使用需完成 Google 要求的发布和可能的验证；此时可能需要可验证的自有域名、隐私说明等。workers.dev 是这次先跑通的入口，不等于保证可以完成正式 OAuth 验证。 如果 Google 控制台拒绝当前回调主机，需使用你可验证的自有域名，不要绕过它的校验。

10. 连接一个频道

  1. 在平台 连接与设置 → 连接具体频道。
  2. 要采收入，勾选 同时申请收入只读权限。
  3. 点 前往 Google 授权频道。
  4. 选择有频道访问资格的 Google 账号，再选择具体频道，批准只读权限。
  5. 返回平台后核对频道名称，确认不是同名的其他频道。
  6. 要接入其他频道，重复这个流程。

一个 Google 账号在 Studio 里能切换 18 个频道，不代表一次 OAuth 就一定返回 18 个。程序已做分页，没有写死 10 个上限；Google 的频道身份和角色资格仍决定能返回哪些频道。只有 Studio 邀请权限的身份可能无法通过 API 读取；让实际所有者或具备相应 API 资格的身份授权。收入还需 monetary 只读范围和频道资格，并非“管理员”三个字就自动有收入权限。

11. 先验收一个视频

  1. 打开 频道库，对刚连接的频道点击 同步视频库。
  2. 程序跳到 任务中心。查看已保存条数、封面和失败原因；关闭网页也会继续在云端处理。
  3. 完成后进入频道，默认按累计播放量排序。
  4. 点击一个视频 查看。
  5. 点击 采集此视频（或频道页的“采集数据”），选这个视频，先采默认报表。
  6. 日期先选最近 28 天，结束日先留到 2—3 天前，减少最新数据未处理的影响。
  7. 完成后刷新该视频；曲线横轴为视频内时间，移动鼠标或点击曲线查看位置。
  8. API 留存一般是按视频总长度的 1% 分段；42 分钟视频每段约 25.2 秒。区间提示不表示逐秒测量。
  9. 用同一频道、视频、日期、来源与 Studio 核对。Studio 概览的周期数据与“自发布以来”的留存卡片可能不是同一日期范围，不能直接混比。
  10. 收入任务若显示缺少权限，回到连接页补授权；无数据和零值在界面中分开显示。

覆盖面与 CTR 另开任务。 它依赖 YouTube Reporting 日报：初次建任务后不会立即拥有全部历史。显示等待时稍后点继续检查，缺失日期不会填成零。单位未可靠确认前不显示百分比；拿同一天同视频的 Studio 对照后再选“0.05 表示 5%”或“5 表示 5%”。Reporting 报表说明 ↗

Studio 独有、API 不提供的指标：在单视频页面使用 导入 Studio CSV，选择正确视频和日期。当前 CSV 导入默认只对管理员可见，避免员工从不固定列名中看到收入/CTR。

验证通过后再选前 20 条、最后全频道。第一次不要同时对全部频道勾选全部报表。

12. 员工登录与权限

每位员工做两处配置：

  1. Cloudflare Access 的 Allow 策略中加入员工登录邮箱。
  2. 平台 人员与权限 → 添加成员 中填同一个邮箱。
  3. 角色选择 数据整理成员。
  4. 勾选允许看的频道。
  5. 不要勾 CTR、收入，该员工就只能看获准的基础数据并整理备注。
  6. “采集”和“导出”按需要单独开启。
  7. 保存后让员工用平台网址登录。

验收：用员工的独立浏览器或无痕窗口登录，确认看不到连接设置、收入和 CTR；能看的频道正确。不要把管理员浏览器会话共享给员工。

平台中停用员工会立即阻止业务数据读取；离职时也从 Access 邮箱名单移除。管理员角色拥有全权限，不适合只负责整理数据的人员。

13. 日常使用和失败恢复

  • 看已保存数据：直接打开平台，选择频道和视频，无需重新采集。
  • 想获取最新数据：同步目录更新标题和累计播放量；采集报表更新选定统计周期。YouTube 有处理延迟，这不是秒级实时接口。
  • 对比频道：先给各频道采同一周期的观看汇总，再在“频道对比”选 2—6 个频道。使用官方频道汇总，不用已采的几个视频相加冒充整个频道。
  • 任务中心显示“有项目待处理”：点详情，看具体是权限、等待生成、无数据还是失败，再点“继续 / 重试”。
  • 点采集后网络断开：先重新登录看任务中心，不要连续重复创建任务。
  • 恢复旧任务前，同一频道同类新任务要先完成或取消。
  • 全频道第一次采集可能很久：步骤总数会随着目录和报表展开而增长，不显示不可信的固定百分比。
  • 新 Google 项目可能有配额限制。遇到 quotaExceeded 时等配额恢复或到 Google Cloud 查看，不要不停重试。

14. 备份、删频道与这版的边界

本版保存数据和缩略图，不保存视频。因此即便有时间点，频道视频删除后也不能在这里回放。

可下载的 频道 JSONL 含视频字段与获准报表，不含封面二进制、授权令牌或完整数据库。不要把这个导出按钮当成完整灾备。

管理员完整备份应包含：

  1. D1 数据库导出。控制台有 Export 就用它；没有时可安装 Node.js，在项目目录依次执行：
npm ci
npx wrangler login
npm run build
npx wrangler d1 export feifan-web-db --remote --config wrangler.generated.jsonc --output ../feifan-web-db-backup.sql

登录时选择本项目所在 Cloudflare 账号。导出文件放在代码目录之外，不上传 GitHub。

  1. 私有 R2 桶文件。少量可在控制台逐个下载；整桶批量备份可用支持 R2 S3 的工具（例如 rclone），凭据仅由管理员保存，按 R2 的 rclone 指南 ↗ 配置到一个独立备份目录。本版没有把批量备份和恢复封装进 UI。
  2. TOKEN_KEY，单独保存在密码管理器。没有该密钥，恢复数据库后无法解密现有授权。

彻底删除 YouTube 频道的需求，不能直接等同于永久保留 API 副本。 YouTube 对 API 数据有持续授权复核、更新与删除要求；统计数据的长期保存也有条件。官方数据保存规则 ↗

这版没有自动化的 30 天复核、撤权清理和完整恢复演练，定位为云端验证版。拟删除频道的档案，应先把自有原始资料、人工导出和 API 数据分清来源，再设计可长期保存的归档流程。当前不要因“任务完成”就删除原频道，尤其是仍有缺失报表时。

同样，以下还没完成：旧本地数据库一键迁移、自动定时刷新、批量全站 Studio 抓取、对全部后台指标的覆盖、正式 Google OAuth 审核。它们没有被假装成已经可用的功能。

15. 更新版本

  1. 把新版本代码提交到 GitHub 的 main。
  2. Cloudflare 自动构建并部署。
  3. 保持 cloudflare.config.json 指向同一个专用 D1 / R2 / 队列。
  4. 本项目部署命令保留 Cloudflare 中已填写的运行变量，不要求重新填密钥。
  5. 数据不在 GitHub 中，常规代码更新不会重置 D1 / R2。
  6. 有数据库迁移的版本必须先备份并看该版本说明，不要自行删除表。
